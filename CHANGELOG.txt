ESCALADE PRO — JOURNAL DES TRANSFORMATIONS
By C. Guilhem
======================================

v3.0.3 — Identifiants Firebase renseignés
--------------------------------------
- Le projet Firebase de Christophe (escalade-pro-3cd6d) n'avait en fait
  jamais été configuré : c'était la cause réelle des enregistrements qui
  ne se faisaient pas (voies, passages, mais aussi vidéos et
  évaluations). Les vrais identifiants sont maintenant renseignés dans
  `src/firebase.js`.
- Rappel : la base Firestore doit être créée (pas Realtime Database) et
  ses règles de sécurité doivent autoriser les 4 collections utilisées
  (voir README).

v3.0.2 — Rendre l'enregistrement d'un passage visible et fiable
--------------------------------------
- Après un audit complet du code d'enregistrement, aucune anomalie
  logique n'a été trouvée dans le calcul de la difficulté ou dans
  l'écriture du passage ; en revanche, si l'enregistrement échoue côté
  serveur (le plus probable : règles de sécurité Firestore qui
  n'autorisent pas encore les nouvelles collections `escalade_config` et
  `escalade_passages` créées pour le Suivi de Cycle), l'échec pouvait
  passer inaperçu. Voir le README pour les règles Firestore à vérifier.
- Un passage apparaît désormais immédiatement dans l'historique de
  l'élève dès qu'il clique sur "Enregistrer ce passage" (mise à jour
  optimiste), avec un message de confirmation clair ("✓ Passage
  enregistré : voie X en Y").
- Si l'enregistrement échoue réellement côté serveur, le passage est
  retiré de l'historique et un message d'erreur explicite s'affiche
  ("le passage n'a PAS été sauvegardé"), au lieu d'échouer
  silencieusement.
- Mêmes garanties pour la suppression d'un passage et pour la case
  "corde rangée en lovant" : réaction immédiate à l'écran, annulée
  proprement en cas d'échec côté serveur.

v3.0.1 — Correctif de lenteur sur "Suivi de Cycle"
--------------------------------------
- L'onglet "Suivi de Cycle" rechargeait entièrement les voies et
  l'historique des passages à chaque fois qu'on cliquait dessus (recharge
  serveur à chaque changement d'onglet). Ces données sont désormais
  chargées une seule fois à la connexion de l'élève, puis conservées :
  changer d'onglet est maintenant instantané.
- La case "Corde rangée en lovant" faisait jusqu'à 4 allers-retours
  serveur (suppression puis recréation du passage). Elle ne fait plus
  qu'une seule mise à jour, avec réaction immédiate à l'écran.
- La suppression d'un passage réagit aussi immédiatement à l'écran,
  avant confirmation du serveur.

v3.0.0 — Suivi de cycle sur les 17 voies et code enseignant modifiable
--------------------------------------
- Espace enseignant : nouvelle fonction "Modifier le code d'accès" (code
  actuel + nouveau code + confirmation), remplace le code fixe 4242 codé
  en dur. Le code par défaut reste 4242 tant qu'il n'a pas été changé.
- Espace élève réorganisé en deux onglets principaux :
  - "Connaissance" : reprend tout ce qui existait avant (sous-onglets
    Référentiel et Ma auto-évaluation), inchangé.
  - "Suivi de Cycle" : nouvelle application de suivi des passages sur
    les 17 voies du mur.
- Pour chaque passage, l'élève renseigne : la voie (1 à 17), son rôle
  (Grimpeur ou Assureur), le mode (Moulinette, Moulitête ou Tête), le
  nombre de couleurs de prise utilisées (1, 2 ou 3), la difficulté de la
  voie (chiffre 3 à 7 + lettre a/b/c + "+" optionnel, ex. "5a+"), la
  hauteur atteinte (sommet/chaîne haute, ou numéro du dernier mousqueton
  passé si non atteint), et peut valider que la corde a été rangée en
  lovant. Chaque passage est enregistré et daté ; l'élève retrouve tout
  son historique de cycle pour se souvenir de ses réussites et varier
  ses voies.
- Nouvel onglet enseignant "Voies" : configuration des 17 voies du mur,
  avec la difficulté correspondant à 1, 2 ou 3 couleurs de prise pour
  chacune. Cette configuration sert à pré-remplir (en suggestion,
  modifiable) la difficulté saisie par l'élève selon la voie et le
  nombre de couleurs choisies.
- Dans l'onglet "Élèves & suivi", chaque élève dispose maintenant de
  deux panneaux séparés : "Évaluer (référentiel)" (comme avant) et
  "Suivi de cycle" (nouveau), avec :
  - un bilan des passages enregistrés (nombre de passages, réussites au
    sommet, voies différentes, répartition grimpeur/assureur, meilleure
    réussite),
  - la saisie de l'épreuve finale de cycle : passage Grimpeur (voie,
    difficulté, réussite) et passage Assureur (voie assurée, qualité
    d'assurage), chacun noté séparément,
  - une note de suivi de cycle sur 20, saisie librement par l'enseignant
    à partir de l'ensemble de ces informations.
- La fiche de chaque élève dans "Élèves & suivi" affiche désormais aussi
  le nombre de passages enregistrés et, si elle existe, la note de
  suivi de cycle.

v2.0.0 — Connexion élève, import de classes et refonte de l'espace enseignant
--------------------------------------
- Nouvelle icône de l'application (montagne + mousqueton), déclinée en
  favicon, icône PWA (192/512) et icône iOS.
- Connexion élève reprise à l'identique du principe de Course de Durée Pro :
  l'élève choisit sa classe, trouve son nom dans la liste, puis saisit son
  code PIN personnel (défini par lui-même lors de sa toute première
  connexion). Isolation stricte par élève/classe.
- Import des listes de classe repris à l'identique de Course de Durée Pro
  (lui-même aligné sur le moteur d'EPS Pro) : import CSV / Excel (.xlsx) /
  ODS, aperçu brut du fichier, association manuelle des colonnes (Nom,
  Prénom, Nom+Prénom combiné, Classe, Sexe), gestion de l'encodage et du
  séparateur, modes "ajouter" et "remplacer" par classe.
- Espace enseignant protégé par code PIN, réorganisé en deux onglets :
  "Référentiel" (gestion des vidéos par item, comme avant) et
  "Élèves & suivi" (classes, import, ajout/modification/suppression
  d'élève, suppression de classe entière, réinitialisation de PIN,
  évaluation notée par élève).
- L'évaluation n'est plus liée à un nom tapé librement : elle est
  désormais rattachée à l'identité de l'élève connecté (auto-évaluation
  élève) ou à l'élève sélectionné dans la classe (évaluation notée par le
  professeur, sur 20). Les deux évaluations sont conservées séparément et
  affichées dans la fiche de l'élève.
- "Escalade Pro by C. Guilhem" et le numéro de version affichés en
  discret à côté du titre sur chaque page (dans l'en-tête).
- Passage de l'application à la même base technique que les autres
  applications (React/Vite/Tailwind, PWA installable via vite-plugin-pwa).
- Ce fichier CHANGELOG.txt est désormais inclus et mis à jour dans chaque
  zip livré.

v1.0.0 — Première version
--------------------------------------
- Création de l'application "Escalade Pro", structurée comme Gym Pro
  (React/Vite, GitHub, Vercel, Firebase).
- Référentiel organisé en 5 modules : Sécurité & vérification visuelle,
  Installation dans le baudrier, Nœuds (nœud de huit, nœud de vache, nœud
  du pendu, nœud d'arrêt), Assurage à 5 points, Lovage et rangement de
  la corde.
- Ajout et gestion de vidéos par item (mode Prof) : une vidéo de
  démonstration + vidéos d'apprentissage par phases, modifiables à tout
  moment, sauvegardées sur Firebase (Firestore).
- Évaluation :
  - Mode Élève : auto-évaluation par case à cocher, compétence par
    compétence, avec décompte des compétences maîtrisées.
  - Mode Prof : évaluation à 3 niveaux par item (Non acquis / En cours /
    Acquis), calcul automatique d'une note globale sur 20.
  - Les évaluations sont enregistrées sur Firebase avec le nom de l'élève.
- Mode Élève / Mode Prof (bascule simple, sans code d'accès pour l'instant).
- Version affichée en discret à côté du titre, avec la mention "By C. Guilhem".
- Bandeau d'avertissement rappelant que le contenu pédagogique de base est
  à vérifier et compléter avant utilisation avec les élèves.
